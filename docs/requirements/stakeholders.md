# 2. 이해관계자 및 사용자

주 사용자는 대시보드로 산림 상태를 감시하는 관제 담당자이며, 메이커톤 데모에서는 이 사용자 관점의 시나리오를 기준으로 기능을 검증한다.

| 사용자 | 역할 | 핵심 요구 |
| --- | --- | --- |
| 관제 담당자 (산림청·지자체) | 대시보드로 지역별 위험도 감시, 경보 확인 후 대응 지시 | 위험 지역을 지도에서 한눈에 파악, 경보 즉시 인지, 센서 이력 조회 |
| 지역 주민 | 위험 정보 수신 및 대피 (향후 확장) | 쉬운 표현의 위험 알림, 대피 판단에 필요한 정보 |
| 시스템 관리자 | 노드 등록·위치 관리, 장애 노드 확인 | 노드 상태(통신 두절, 배터리) 확인, 노드 추가 |
| 심사위원 (메이커톤) | 결과물 평가 | 실시간 동작 시연, 문제 정의와 해결의 연결성 |

## 팀 역할 분담

| 이름 | 역할 | 담당 영역 | 주로 맡는 이슈 라벨 |
| --- | --- | --- | --- |
| 고희경 (팀장) | H/W 개발 | 센서 노드 회로, 노드 펌웨어 | `노드` |
| 김태호 | 기획 | 요구사항 정의, 위험도 판단 기준, 발표 | `비기능`, `위험도엔진` (판단 기준) |
| 임동섭 | S/W 개발 | 게이트웨이, 서버, 위험도 엔진 | `게이트웨이`, `서버`, `위험도엔진` |
| 조연우 | 디자인 | 웹 대시보드 UI, 발표 자료 | `대시보드` |
